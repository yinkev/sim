# Review Packet — Center Dogfoodable Alpha Architecture

## Objective

Review the proposed Center dogfoodable alpha architecture before implementation.

Center is the working name for the daily operating surface inside Sim.

## Decision stage

```text
pre-implementation
```

## Proposal summary

Build Center as a local-first, multi-user, event-sourced operating surface with:

- isolated user profiles
- event stream
- loop model
- local prediction layer
- visual surface for loops, agents, progress, blockers, evidence, and next actions
- scheduler integration as a module
- Learn / Understand integration
- worker/governor review protocol before implementation

Workflow remains a feature module. Center is the operating surface.

## Constraints

- Do not start by modifying product code until CPU/RAM stabilization is addressed.
- Do not make Center import the full workflow editor/block registry by default.
- Do not create global cross-user data sharing by default.
- Do not rely on opaque LLM predictions as the source of truth.
- Do not use dark/cyberpunk/AI-slop aesthetics by default.
- Use standard terminology and boring names.

## Known repo risk

Sim currently has a heavy workspace route graph.

Existing perf note identifies this chain:

```text
workspace shell/layout -> workflow stores -> getBlock -> blocks barrel -> registry -> hundreds of block modules
```

This is why Center must stay lightweight and avoid inheriting workflow editor costs.

## Governor A position

This architecture is directionally right, but it may still be too broad for a first dogfoodable alpha.

The first implementation should probably be:

1. CPU/RAM stabilization.
2. Local profile and event store.
3. Loop model.
4. Lightweight Center visual surface.
5. Transparent baseline predictions.
6. Scheduler as a connected module, not central engine.
